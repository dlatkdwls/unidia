# 열린 항목 (문서 정합성 점검 결과)

SRS, 아키텍처 문서, RQ 트래커를 교차 점검해 확인한 정리 대상이다. 해결되면 체크하고 해당 문서에 반영한다.

## 문서 간 불일치
- [ ] **내보내기 형식**: SRS 3.1은 "Mermaid 코드 다운로드"를 포함하지만 REQ-08(PNG/JPG)과 RQ-09에는 없음 → 요구사항 추가 또는 3.1 수정
- [ ] **2.2의 "흑백 4색 이상"** 문구를 REQ-09("그레이스케일에서 4색 명도 구분")에 맞춰 수정
- [ ] **성능 단위**: RQ 트래커는 "객체 30개(노드 및 엣지)", SRS 3.3은 "노드 30개" → 하나로 통일

## SRS에 없는 기능
- [ ] Undo/Redo (아키텍처에는 Command 패턴으로 설계됨)
- [ ] 저장/불러오기 (3.4는 JSON 저장만 언급, REQ 없음)
- [ ] 단축키 (RQ-10)
- [ ] 보안 (RQ-0305: 인증·클라우드 저장 미구현)

## 검증 가능성 부족
- [ ] REQ-04, 06, 08, 09의 확인 기준에 수치·허용 오차 부여 (해상도, 명도 차이 등)
- [ ] 3.6 사용성·출력 품질 문장을 측정 가능한 기준(성공률, 소요 시간 등)으로 변경
- [ ] 3.3 성능 측정 환경(브라우저, 기기) 명시

## 기타
- [ ] REQ-06, REQ-09가 "핵심 차별화/핵심 목표"인데 우선순위가 "중"인 근거 정리
- [ ] 코드 영역 항상 표시 요구가 3.1, REQ-10, 2.2, 2.4에 반복됨 (중복 정리 여부)

## UI 설계 단계 원칙 (예정)
UI 설계 시 사용자를 유도하거나 선택을 방해하는 설계(다크 패턴)를 피한다. 검토 기준 세 가지:
1. **사실인가?** 표시하는 정보에 실제 근거가 있는가
2. **알 수 있는가?** 결정 전에 조건과 결과를 읽을 수 있는가
3. **거절 가능한가?** 취소·되돌리기가 발견 가능하고 실행 가능한가

적용 예: 파괴적 동작은 Undo 제공, 내보내기 옵션 기본값은 끔, 취소·닫기 문구는 중립적으로, 설정 문구는 긍정형으로, 버튼 라벨은 실제 동작과 일치.

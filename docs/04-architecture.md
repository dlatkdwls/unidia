# 04. 아키텍처 설계

## 아키텍처 스타일 분류

UniDia는 **Layered Architecture**(UI / 코어 / 렌더링 / 내보내기 4계층)를 기본 구조로 하고, 그 안에서 코드 에디터·GUI 캔버스·다이어그램 모델이 통신하는 방식은 **MVC 패턴**과 거의 일치한다.

| 역할 | UniDia 구성요소 |
| --- | --- |
| Model | 다이어그램 모델 (노드·엣지·좌표) |
| View | GUI 캔버스 + 렌더링 엔진 |
| Controller | 코드 에디터 (사용자 입력을 모델에 반영) |

## 적용 GoF 디자인 패턴

| 패턴 | 적용 위치 | 이유 |
| --- | --- | --- |
| Observer | 다이어그램 모델 → 직렬화기 · 렌더러 | 모델이 바뀌면 구독자(코드 에디터, 캔버스)에게 자동 알림 → 양방향 동기화(REQ-03) 구현에 적합 |
| Command | 실행취소/재실행 (Ctrl+Z/Y) | 사용자의 편집 동작을 객체화하여 히스토리 관리 |
| Strategy | 내보내기(PNG/JPG), 다이어그램 타입별 렌더러 | 형식·타입별로 알고리즘을 교체 가능하게 해 REQ-07, REQ-08 확장성 확보 |
| Facade | RenderEngine | 복잡한 Mermaid.js API를 감싸서 단순한 창구로 노출, 렌더링 엔진 교체 시 영향 최소화(DIP) |

## 품질 목표 (ISO/IEC 25010 기준)

| 품질 속성 | UniDia 적용 |
| --- | --- |
| 성능 효율성 | 코드 입력 후 1초 이내 렌더링 (REQ-01, 3.3), 드래그·마그네틱 갱신 60fps 이상 (REQ-02, REQ-04, 3.3) |
| 유지보수성 | 새 다이어그램 타입을 기존 코드 수정 없이 추가(OCP, Strategy 패턴) |
| 호환성/이식성 | 출력(PNG/JPG)이 논문 편집기·문서에 문제 없이 삽입되어야 함 |
| 사용성 | 코드/GUI 중 하나만 알아도 완성 가능 (양방향 동기화) |

> 원본의 아키텍처 다이어그램(패키지 구조) 이미지는 이 저장소에 포함하지 않았다. 필요하면 `docs/images/`에 추가한다.
>
> 원본 Notion에서는 60fps 항목이 REQ-01을 인용했으나, REQ-01은 1초 렌더링 요구이므로 여기서는 REQ-02, REQ-04로 바로잡았다.

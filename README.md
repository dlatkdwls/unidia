# UniDia

> Mermaid의 **텍스트 코드 작성 편의성**과 UMLet의 **자유로운 수동 편집**을 결합한 웹 기반 다이어그램 도구
> 핵심 목표: **논문에 삽입해도 문제없는 출력 품질** (폰트 깨짐·화살표 고정 문제 해결)

소프트웨어공학 수업 팀 프로젝트(6인)로 진행 중인 가칭 **UniDia**의 요구사항·설계 문서를 정리한 저장소입니다.

> **현재 단계: 요구 분석 · 아키텍처 설계** — 구현 코드는 아직 없으며, 아래 내용은 SRS(소프트웨어 요구사항 명세서)와 설계 문서를 기준으로 합니다. 수치와 범위는 팀 회의에서 확정되었지만 이후 변경될 수 있습니다.

## 왜 UniDia인가

| 도구 | 잘하는 것 | 아쉬운 점 |
| --- | --- | --- |
| Mermaid | 코드로 빠르게 큰 구조 작성 | 크기 조절 시 폰트 깨짐, 화살표 경로 고정, 인쇄·논문용 품질 부족 |
| UMLet | GUI로 정교한 수동 편집 | 코드 기반 빠른 초안 작성이 어려움 |

UniDia는 코드로 큰 그림을 빠르게 그리고, GUI로 세부를 UMLet 수준으로 다듬는 두 방식을 한 화면에서 함께 제공합니다.

## 주요 기능

- **실시간 렌더링** — Mermaid 문법 코드를 입력하면 1초 이내에 다이어그램 생성
- **GUI 편집** — 노드 드래그 이동 및 크기 조절
- **코드 ↔ GUI 동기화** — GUI에서 수정한 위치·크기·엣지 경로는 별도 데이터로 관리되어 코드를 고쳐도 유지
- **마그네틱 커넥터** — 노드를 옮기면 연결된 화살표가 자동으로 따라옴
- **엣지 경로 조정** — 꺾이는 지점을 직접 드래그해 원하는 형태로 조정
- **스케일 안정형 폰트** — 확대·축소해도 도형 비율에 맞게 폰트 스케일링
- **다이어그램 유형** — 클래스, 시퀀스 다이어그램 (2종)
- **출판용 내보내기** — 고해상도 PNG/JPG, 흑백 인쇄 시에도 최소 4가지 색 구분
- **항상 함께 표시되는 코드 편집 영역** — 코드 없는 GUI 전용 모드는 제공하지 않음

## 요구사항 요약

### 기능 요구사항

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| REQ-01 | Mermaid 코드 입력 시 실시간 렌더링 (1초 이내) | 상 |
| REQ-02 | GUI에서 노드 드래그 이동 및 크기 조절 | 상 |
| REQ-03 | 코드와 GUI의 논리 구조 동기화, 시각적 편집 정보는 별도 데이터로 유지 | 상 |
| REQ-04 | 노드 이동 시 연결된 엣지 자동 재배치 (마그네틱 커넥터) | 상 |
| REQ-05 | 엣지 경로(꺾이는 지점)를 직접 드래그해 조정 | 상 |
| REQ-06 | 확대·축소 시 폰트가 도형 크기 비율에 맞게 스케일링 | 중 |
| REQ-07 | 클래스·시퀀스 다이어그램 생성 (유형별 객체·편집 기능 별도 정의) | 상 |
| REQ-08 | 고해상도 PNG 또는 JPG로 내보내기 | 상 |
| REQ-09 | 흑백(그레이스케일) 인쇄 시에도 최소 4가지 색상이 구분됨 | 중 |
| REQ-10 | 코드 편집 영역은 항상 GUI 캔버스와 함께 표시 | 상 |

### 비기능 요구사항

- **성능**: 코드 입력 후 렌더링 1초 이내, 노드 30개 규모에서 드래그·마그네틱 재배치 60fps
- **데이터**: 다이어그램은 JSON(노드·엣지 좌표, 스타일, 수동 경로 포인트 포함)으로 저장하며 Mermaid 코드와 상호 변환 가능
- **설계 제약**: 렌더링 엔진은 Mermaid.js 기반, 마그네틱·경로·폰트 스케일링은 별도 오버레이로 구현, GUI 편집 결과는 적법한 Mermaid 문법으로 직렬화 가능
- **시스템 속성**: 사용성(코드/GUI 중 하나만 알아도 완성 가능), 출력 품질, 유지보수성(새 다이어그램 유형을 플러그인 형태로 추가)
- **제약**: 웹 브라우저 기반, 오프라인 미지원, Mermaid 미지원 표기법은 우선 제외

## 아키텍처

**Layered Architecture**(UI / 코어 / 렌더링 / 내보내기 4계층)를 기본으로, 코드 에디터·GUI 캔버스·다이어그램 모델 사이의 통신은 **MVC**와 거의 일치합니다.

| 역할 | 구성요소 |
| --- | --- |
| Model | 다이어그램 모델 (노드·엣지·좌표) |
| View | GUI 캔버스 + 렌더링 엔진 |
| Controller | 코드 에디터 (사용자 입력을 모델에 반영) |

### 적용 디자인 패턴 (GoF)

| 패턴 | 적용 위치 | 이유 |
| --- | --- | --- |
| Observer | 다이어그램 모델 → 직렬화기·렌더러 | 모델 변경 시 구독자에게 자동 알림 → 양방향 동기화(REQ-03) |
| Command | 실행취소/재실행 (Ctrl+Z/Y) | 편집 동작을 객체화해 히스토리 관리 |
| Strategy | 내보내기(PNG/JPG), 다이어그램 유형별 렌더러 | 형식·유형 교체 가능 → REQ-07, REQ-08 확장성 |
| Facade | RenderEngine | Mermaid.js API를 감싸 렌더링 엔진 교체 영향 최소화 |

### 품질 목표 (ISO/IEC 25010)

| 품질 속성 | 적용 |
| --- | --- |
| 성능 효율성 | 1초 이내 렌더링, 드래그·마그네틱 갱신 60fps |
| 유지보수성 | 새 다이어그램 유형을 기존 코드 수정 없이 추가 (OCP, Strategy) |
| 호환성/이식성 | PNG/JPG 출력이 논문 편집기·문서에 문제없이 삽입 |
| 사용성 | 코드/GUI 중 하나만 알아도 완성 가능 |

## 대상 사용자

- **개발자** — 코드로 빠르게 큰 구조를 그리는 것을 선호
- **연구자/논문 작성자** — 출판 품질의 정교한 다이어그램 필요
- **기획자/디자이너** — GUI 기반 세부 편집 선호
